Public Windows worker: no EMO_CI_TOKEN, named secrets, release credentials, age identity or signing keys. Public runners do not give a hard boundary against untrusted code/network egress. Do not feed private source to this draft or merely toggle an input/visibility override.

Trust separation: the known existing EMO_CI_TOKEN may be used only in an isolated authenticated control step to check the official product request or download GitHub ciphertext. It must not exist in the public Windows build/test job or the publisher. Validate job/run repository ID/attempt, trusted dispatcher and workflow SHA, immutable source SHA and packager SHA, exact requested version and identities, positive job conclusion, artifact ID and platform-provided digest before decryption. A caller's successful status, plaintext hash or public encryption key alone is not provenance. Reject stale, mismatched, duplicate or unverified output. Tag input cannot authorize publication.

Public artifact: exactly one .tar.age per target, no plaintext logs or payloads. Runtime reports only the exact fixed identity+archive-validation records; optionally use a separate previously audited bounded diagnostic envelope for logs, never place raw logs in a package. Packages can be large; verify hosted runner disk, upload quota, retention and 2 GiB release asset limits with a non-release run. Do not make CI binary transfer a required check before a real two-target round trip.

Private receiver: decrypt only in an isolated product verification job using its existing out-of-band age identity, never store identity in public env. If there is no approved private verification entry/identity, stop. Recover into previously nonexistent per-target directories and use output only if recover returns success; perform existing master_release.py verify, product Designer package icon check and validate full frozen/native evidence provenance. This draft does not make the external encrypted transport an authority for publish.

Product publication: remain on the private product-only protected matching version tag, explicit release intent; product GITHUB_TOKEN contents:write only in the narrow publish job, not from EMO_CI_TOKEN. Enforce same immutable source/packager/tag, verify six names/sizes/SHA256s, draft-first verification, and failure/rollback. No workflow defaults activated, keys no changes and no Release mutation in this stage.
